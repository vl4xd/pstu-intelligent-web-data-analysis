## 1. Описание проекта

Проект представляет собой систему автоматического анализа и семантической обработки видеоданных. Программа собирает видео и метаданные, извлекает визуальную и аудиосоставляющие, обнаруживает объекты, распознаёт речь, формирует временные события и предоставляет результаты через веб-интерфейс.

В качестве предметной области выбраны спортивные видеозаписи: футбол, баскетбол, теннис, лёгкая атлетика и хоккей.

Основные используемые технологии:

- **yt-dlp** — получение видеоматериалов и метаданных с видеохостингов.
- **FFmpeg / FFprobe** — декодирование видео, извлечение аудио и получение технических характеристик файлов.
- **YOLO11n (Ultralytics)** — обнаружение объектов на видеокадрах.
- **OpenAI Whisper (base)** — распознавание речи и формирование транскрипта с временными метками.
- **NumPy** — обработка аудиоданных и вычисление характеристик сигнала.
- **scikit-learn** — векторизация текстов с помощью TF-IDF и тематическая кластеризация KMeans.
- **Gradio** — интерактивный веб-интерфейс для поиска и просмотра результатов анализа.
- **PyTorch** — выполнение нейросетевых моделей, в том числе на GPU.

## 3. Архитектура и принцип работы

Система реализована в виде последовательного конвейера обработки видео.

### 3.1. Сбор видеоданных

Для эксперимента подготовлена выборка из пяти спортивных видеозаписей, полученных с Rutube.

С помощью yt-dlp извлекаются:

- идентификатор и название видео;
- продолжительность;
- описание и доступные сведения об источнике;
- ссылка на исходную видеозапись.

Видео сохраняются в `data/raw/`, метаданные — в `data/metadata/videos.json`.

Для получения технических характеристик используется FFprobe: продолжительность, параметры видеопотока, разрешение и другие доступные характеристики файла.

### 3.2. Декомпозиция видео

Каждая видеозапись разделяется на визуальную и аудиосоставляющие.

**Извлечение кадров:**

- Кадры выбираются равномерно на протяжении всей видеозаписи.
- Для каждого видео извлекается не более 400 кадров.
- Минимальный интервал между кадрами — 1 секунда.
- Для длинных видео интервал автоматически увеличивается, чтобы выборка охватывала всю продолжительность ролика.

Изображения сохраняются в `data/frames_v2/`.

**Извлечение аудио:**

- Аудиодорожка извлекается с помощью FFmpeg.
- Каналы преобразуются в моно.
- Частота дискретизации устанавливается на 16 кГц.
- Результат сохраняется в формате WAV в `data/audio_v2/`.

Такой подход позволяет анализировать видео без необходимости обрабатывать каждый исходный кадр, снижая вычислительную нагрузку.

### 3.3. Визуальный анализ

Для обнаружения объектов используется предобученная модель YOLO11n.

Параметры детекции:

- модель: YOLO11n;
- размер изображения: 640 пикселей;
- порог уверенности: 0,35;
- пакетная обработка кадров;
- выполнение на GPU при наличии совместимого CUDA-устройства.

Для каждого обнаруженного объекта сохраняются:

- название класса;
- уверенность модели;
- координаты ограничивающей рамки;
- временная метка кадра.

Результаты позволяют определять присутствие людей, спортивного инвентаря и других объектов на протяжении видеозаписи.

### 3.4. Анализ аудио и распознавание речи

Для распознавания речи применяется OpenAI Whisper с моделью `base`.

Аудиодорожка обрабатывается частями продолжительностью до 600 секунд. Это позволяет работать с длинными видеозаписями и сохранять промежуточные результаты.

Для каждого распознанного речевого сегмента сохраняются:

- время начала;
- время окончания;
- распознанный текст.

Дополнительно рассчитываются характеристики аудиосигнала:

- среднеквадратичная амплитуда (RMS);
- уровень сигнала в децибелах относительно полной шкалы (dBFS).

### 3.5. Выявление временных событий и смены сцен

На основе результатов визуального и аудиоанализа формируются временные события.

Реализованы:

- группировка наблюдений обнаруженных объектов по временным меткам;
- объединение близких наблюдений в события;
- использование речевых сегментов в качестве событий;
- обнаружение вероятных смен сцен по различию цветовых гистограмм выбранных кадров.

Каждое событие содержит временную информацию и описание.

**Ограничения:** смена сцены определяется по изменению визуальной гистограммы, а не посредством полноценного семантического распознавания сцен. Обнаружение объектов основано на выборочных кадрах, поэтому временные границы событий являются приближёнными.

### 3.6. Тематическая группировка видео

Для экспериментальной тематической группировки используется комбинация TF-IDF и KMeans.

В текстовое представление видеозаписи включаются:

- название;
- описание;
- дисциплина и доступные теги;
- текст транскрипта;
- названия обнаруженных объектов.

Для оценки качества кластеризации рассчитывается коэффициент силуэта (Silhouette Score).

Полученная выборка содержит всего пять роликов разных спортивных дисциплин. Поэтому кластеризация рассматривается как эксперимент, а не как надёжная модель автоматической классификации.

В интерфейсе тематическое распределение отображается по дисциплинам из метаданных. Оно не является результатом KMeans-кластеризации.

### 3.7. Управление моделями

Для управления весами нейросетевых моделей реализован модуль `src/model_manager.py`.

Он обеспечивает:

- проверку наличия локальных весов;
- автоматическую загрузку YOLO11n при отсутствии файла `models/yolo/yolo11n.pt`;
- автоматическую загрузку Whisper Base при отсутствии файла `models/whisper/base.pt`;
- сохранение загруженных весов в каталогах проекта;
- повторное использование уже загруженных моделей в пределах текущего процесса.

Таким образом, пользователю не требуется вручную скачивать файлы моделей. Загрузка выполняется при первой необходимости, а в дальнейшем используются сохранённые локальные копии.

## 4. Веб-интерфейс

Для взаимодействия с системой используется Gradio.

Интерфейс предоставляет следующие возможности:

- просмотр каталога обработанных видеозаписей;
- поиск видео по названию, дисциплине, транскрипту, объектам и событиям;
- просмотр выбранного видео во встроенном плеере;
- отображение статистики обработки;
- просмотр обнаруженных объектов;
- интерактивная временная шкала событий;
- переход к нужному моменту видео нажатием на временную метку;
- отображение тематического распределения видеозаписей;
- добавление нового видео по ссылке с выбором спортивной дисциплины.

При добавлении видео система получает метаданные, загружает исходный файл при необходимости, подготавливает необходимые модели, выполняет анализ и обновляет каталог. Повторное добавление уже обработанного видео не требует повторного анализа.

Открытие веб-интерфейса само по себе не запускает загрузку моделей. Они подготавливаются при добавлении видео через интерфейс.

## 8. Ограничения и направления развития

Текущая реализация является прототипом мультимодальной системы анализа видеоданных.

Основные ограничения:

- визуальный анализ выполняется на выборочных кадрах, а не на каждом кадре исходного видео;
- обнаружение объектов не заменяет распознавание спортивных действий;
- смена сцен определяется по визуальному отличию кадров;
- качество распознавания речи зависит от фонового шума, музыки и особенностей комментирования;
- тематическая кластеризация требует расширения выборки и улучшения текстовых признаков;
- события по объектам отражают наблюдения на выбранных кадрах, а не непрерывное отслеживание объектов.

В дальнейшем систему можно расширить трекингом объектов, распознаванием действий, улучшением качества ASR, использованием текстовых эмбеддингов и увеличением объёма тематической выборки.

Для упрощения установки реализована автоматическая загрузка и локальное хранение весов YOLO11n и Whisper Base. Пользователю не требуется вручную получать файлы моделей.

Работоспособность конвейера проверена на пяти видеозаписях разных спортивных дисциплин. Реализовано добавление новых видео непосредственно через интерфейс.

Таким образом, создан прототип мультимодальной системы, объединяющей визуальный, аудиальный и текстовый анализ видеоданных с привязкой результатов к временной структуре видео.
