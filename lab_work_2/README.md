# Лабораторная работа 1: Граф информационно-аналитических веб-ресурсов

**Автор:** Платонов Владислав, АСУ8-25-1м

Программа на Python для сбора текстовой информации с веб-ресурсов, посвящённых металлургической промышленности Российской Федерации и стран ближнего зарубежья, извлечения ключевых терминов и построения интерактивного графа тематических связей между сайтами.

## Принцип работы

Программа выполняет обработку в несколько этапов:

1. **Подготовка списка ресурсов.** Из TXT-файла читаются начальные URL. Проверяются протокол, наличие доменного имени и корректность порта. Повторяющиеся адреса не добавляются в список обхода.
2. **Сбор страниц.** Scrapy загружает HTML-страницы. При необходимости паук переходит по ссылкам, оставаясь в пределах хоста исходного сайта и соблюдая заданную глубину обхода.
3. **Извлечение текста.** BeautifulSoup разбирает HTML. Из текста страницы формируется корпус из абзацев, заголовков и элементов списков.
4. **Кэширование.** Полученные тексты и найденные ссылки сохраняются в `cache.json`. При последующих запусках сохранённые страницы могут использоваться повторно.
5. **Извлечение терминов.** `rutermextract` выделяет нормализованные ключевые термины. Результаты группируются по доменам.
6. **Построение графа.** Для каждой пары сайтов вычисляется пересечение множеств терминов. Если общих терминов не меньше заданного порога, между сайтами создаётся ребро.
7. **Сохранение результата.** Интерактивный граф PyVis сохраняется в HTML-файл в директории `results/` и открывается в браузере.

Таким образом, схема обработки выглядит следующим образом:

```text
TXT со списком URL
        |
        v
Проверка и удаление повторов
        |
        v
Scrapy: обход и загрузка HTML
        |
        v
Извлечение видимого текста
        |
        +------> JSON-кэш (cache.json)
        |
        v
Извлечение терминов по сайтам
        |
        v
Сравнение множеств терминов
        |
        v
Граф связей (PyVis, HTML)
```

## Возможности

- сбор данных с нескольких начальных веб-ресурсов из одного TXT-файла;
- проверка URL перед запуском обхода;
- ограничение глубины перехода по внутренним ссылкам;
- ограничение общего количества обрабатываемых уникальных URL;
- обход ссылок только в пределах хоста соответствующего начального адреса;
- соблюдение `robots.txt`;
- задержка между запросами и ограничение параллельных запросов к одному домену;
- повторное использование ранее загруженных страниц через JSON-кэш;
- принудительный запуск без чтения кэша;
- извлечение ключевых терминов отдельно для каждого домена;
- построение интерактивного графа с порогом по числу общих терминов;
- сохранение каждого графа в отдельный HTML-файл.

### Назначение файлов

#### `run.py`

Точка входа в приложение. Объединяет этапы работы: чтение и проверку URL, запуск обхода, вывод статистики, извлечение терминов и построение графа.

#### `argparser.py`

Формирует интерфейс командной строки с помощью `argparse`. Проверяет входной TXT-файл, глубину обхода, лимит страниц и минимальное количество общих терминов.

#### `txtparser.py`

Читает TXT-файл и проверяет адреса. Принимаются URL с протоколами `http` и `https`, заданным именем хоста и корректным портом. Повторяющиеся адреса добавляются в список отклонённых строк и не передаются пауку.

#### `spider.py`

Содержит Scrapy-паук `GenericSpider`. Он обрабатывает начальные URL, собирает внутренние ссылки и загружает страницы с учётом глубины и лимита. Из HTML извлекается текст элементов `p`, `h1`–`h6` и `li`. Элементы `script`, `style` и `noscript` удаляются перед извлечением текста.

В настройках обхода используются:

- `ROBOTSTXT_OBEY = True` — соблюдение правил `robots.txt`;
- `DOWNLOAD_DELAY = 1.0` — задержка между запросами;
- `CONCURRENT_REQUESTS_PER_DOMAIN = 2` — не более двух одновременных запросов к одному домену;
- `DOWNLOAD_TIMEOUT = 20` — тайм-аут загрузки;
- `RETRY_TIMES = 2` — число повторных попыток.

#### `cacher.py`

Содержит класс `JsonPageCache`, который загружает и сохраняет данные страниц в `cache.json`. Для каждой страницы сохраняются текст, ссылки, HTTP-статус и время получения.

#### `term_extractor.py`

Группирует тексты собранных страниц по доменам и извлекает термины с помощью `TermExtractor` из `rutermextract`. Для одного сайта за один запуск запрашивается не более 200 терминов. Результаты представляются в виде множеств нормализованных строк.

В модуле также добавлен compatibility shim для `inspect.getargspec`, необходимый для использования старой зависимости морфологического анализатора в современных версиях Python.

#### `graph.py`

Строит неориентированный граф с помощью PyVis. Вершины соответствуют доменам, а рёбра — парам сайтов, у которых найдено достаточное количество общих терминов. Размер вершины зависит от количества извлечённых терминов; вес и подпись ребра отражают количество общих терминов. При наведении на элементы графа отображаются подсказки.

Граф сохраняется в `results/graph_ГГГГММДД_ЧЧММСС_микросекунды.html`.

#### `urls/metallurgy.txt`

Список исходных веб-ресурсов, посвящённых металлургической отрасли. В файле можно указать по одному URL на строку.

#### `cache.json`

Локальный кэш ранее загруженных страниц. Создаётся или обновляется автоматически.

#### `example.ipynb`

Jupyter Notebook с описанием исследуемых ресурсов, примерами запуска программы и результатами эксперимента.

## Требования

- Python **3.11 или новее**;
- библиотеки из `requirements.txt`.

В качестве среды разработки использовались Python 3.12 и Scrapy 2.20.0. Scrapy 2.20 требует Python 3.11 или новее; см. [официальную инструкцию по установке Scrapy](https://docs.scrapy.org/en/latest/intro/install.html).

`rutermextract` предназначен для извлечения ключевых слов из русскоязычных текстов. Поэтому результаты для страниц на казахском, английском и других языках могут быть менее точными. Описание библиотеки доступно на [PyPI](https://pypi.org/project/rutermextract/).

## Использование

Запуск из корневой директории проекта:

```bash
python run.py metallurgy.txt
```

Если передано относительное имя TXT-файла, программа ищет его в директории `urls/`. Поэтому для файла `urls/metallurgy.txt` указывается именно `metallurgy.txt`, а не `urls/metallurgy.txt`. Также можно передать абсолютный путь к TXT-файлу.

### Примеры запуска

Обработка только начальных URL с параметрами по умолчанию:

```bash
python run.py metallurgy.txt
```

Увеличить глубину обхода до первого уровня внутренних ссылок и лимит до 50 URL:

```bash
python run.py metallurgy.txt --deep 1 --max-pages 50
```

Использовать порог в пять общих терминов для создания ребра:

```bash
python run.py metallurgy.txt --min-common 5
```

Принудительно не использовать ранее сохранённые страницы:

```bash
python run.py metallurgy.txt --no-use-cache
```

Запуск с несколькими параметрами:

```bash
python run.py metallurgy.txt -d 1 -mp 50 -mc 5
```

Показать справку:

```bash
python run.py --help
```

## Аргументы командной строки

```text
usage: web-resource-graph [-h] [-d N] [--use-cache | --no-use-cache]
                          [-mp N] [-mc N] FILE
```

| Аргумент | Назначение | Значение по умолчанию |
|---|---|---:|
| `FILE` | TXT-файл с исходными URL. Относительный путь ищется в `urls/`. | — |
| `-d N`, `--deep N` | Максимальная глубина обхода. `0` — только начальные URL; `1` — также первый уровень внутренних ссылок. | `0` |
| `--use-cache` | Использовать JSON-кэш. Этот режим включён по умолчанию. | `True` |
| `--no-use-cache` | Не читать страницы из кэша, а загружать их заново. Новые результаты по-прежнему сохраняются в кэш. | — |
| `-mp N`, `--max-pages N` | Максимальное количество уникальных URL, принимаемых к обработке за один запуск. Лимит общий для всех исходных URL. | `25` |
| `-mc N`, `--min-common N` | Минимальное количество общих терминов для создания ребра между двумя сайтами. | `3` |

Для `--deep` допускается целое число от `0`. Для `--max-pages` и `--min-common` допускаются положительные целые числа от `1`.

Ограничение в 200 терминов на сайт задано непосредственно в `run.py` и не является аргументом командной строки.

## Формат результата

Во время выполнения программа выводит:

- количество собранных страниц;
- количество страниц, полученных из кэша;
- количество страниц, загруженных заново;
- ошибки загрузки и соответствующие URL;
- количество извлечённых терминов для каждого сайта;
- количество вершин и рёбер итогового графа;
- путь к созданному HTML-файлу.

Пример фрагмента вывода одного из запусков:

```text
Собрано страниц: 23
Взято из кэша: 14
Загружено заново: 9

Ошибок загрузки: 7
...

Граф успешно создан!
Количество узлов: 19
Количество рёбер: 74
Минимум общих терминов: 3
Файл: .../results/graph_20261115_193911_816984.html
```

Числа в примере относятся к одному конкретному запуску и могут отличаться при последующих запусках из-за доступности сайтов, содержимого кэша и параметров обхода.

### Интерпретация графа

- **Вершина** — сайт, для которого удалось извлечь хотя бы один термин.
- **Размер вершины** — относительное количество извлечённых терминов сайта.
- **Ребро** — наличие не менее `--min-common` общих терминов у двух сайтов.
- **Подпись и толщина ребра** — количество общих терминов.
- **Всплывающая подсказка** — домены, число общих терминов и список общих терминов (до 50 позиций).

Отсутствие ребра не означает, что сайты никак не связаны по тематике: это означает только, что число совпавших извлечённых терминов оказалось ниже заданного порога.

## Особенности и ограничения

1. **Доступность сайтов.** Сервер может вернуть HTTP 403, 409, 429 или 5xx, разорвать соединение либо не ответить за отведённое время. Такие ошибки фиксируются в результате обхода; программа не может гарантировать доступность внешних ресурсов.
2. **Правила сайтов.** Обход выполняется с `ROBOTSTXT_OBEY = True`. Запрет в `robots.txt` и ограничения со стороны сервера могут препятствовать загрузке страниц.
3. **Кэширование.** При включённом кэше ранее сохранённые страницы могут не запрашиваться повторно. Для принудительной загрузки используйте `--no-use-cache`.
4. **Глубина и домен.** Переходы выполняются только по ссылкам в пределах хоста исходного URL. Внешние домены и отдельные поддомены автоматически не обходятся.
5. **Извлечение текста.** Сейчас извлекается содержимое абзацев, заголовков и элементов списков. Общие элементы навигации и подвала сайта могут попадать в текст, если они размечены этими HTML-тегами, и влиять на пересечение терминов.
6. **Язык материалов.** `rutermextract` ориентирован на русский язык. Для многоязычных ресурсов результаты могут быть неполными или неточными.
7. **Лимит терминов.** Для каждого сайта запрашивается не более 200 терминов. Если сайт достиг значения 200, это не доказывает, что в его тексте всего 200 терминов.
8. **Валидация исходного файла.** Некорректные, пустые и повторяющиеся строки не передаются пауку. В текущей версии `run.py` отдельный список таких строк пользователю не выводится.
9. **Сходство по терминам.** Общие элементы меню, корпоративные формулировки и шаблонный текст могут увеличивать число пересечений. Граф отражает сходство извлечённых терминов, а не экспертную оценку содержательной близости ресурсов.

## Устранение типичных проблем

### `ModuleNotFoundError`

Проверьте, что активировано виртуальное окружение, и установите зависимости:

```bash
python -m pip install -r requirements.txt
```

### Ошибка `inspect.getargspec` при импорте `rutermextract`

В `term_extractor.py` уже добавлена совместимость для этой функции, которая была удалена из современных версий Python. Убедитесь, что используется версия файла из проекта.

### Предупреждение или ошибка, связанные с `pkg_resources`

`rutermextract` — старая библиотека. В `requirements.txt` зафиксировано ограничение `setuptools<81` для совместимости с её устаревшими зависимостями. Переустановите зависимости в активном виртуальном окружении, если ограничение не применилось.

### Граф не появился

Проверьте, что:

- в TXT-файле есть корректные адреса;
- удалось загрузить хотя бы одну HTML-страницу с текстом;
- извлечение вернуло хотя бы один непустой набор терминов;
- файл графа создан в `results/`.

### Сайт не загрузился

Проверьте URL и доступность сайта в браузере. Ошибка может быть связана с ограничениями сервера, `robots.txt`, тайм-аутом или временной сетевой проблемой. Повторный запуск можно выполнить с `--no-use-cache`. Не следует отключать соблюдение `robots.txt` только ради обхода запрета.

### Запуск из Jupyter Notebook на Windows

Для Scrapy надёжнее запускать `run.py` как отдельный процесс, а не импортировать его в уже работающий kernel. Пример с потоковым выводом:

```python
import os
import subprocess
import sys
from pathlib import Path

PROJECT_DIR = Path.cwd()

env = {
    **os.environ,
    "PYTHONUNBUFFERED": "1",
    "PYTHONIOENCODING": "utf-8",
    "PYTHONUTF8": "1",
}

proc = subprocess.Popen(
    [sys.executable, "-u", str(PROJECT_DIR / "run.py"),
     "metallurgy.txt", "-mp", "30"],
    cwd=PROJECT_DIR,
    stdout=subprocess.PIPE,
    stderr=subprocess.STDOUT,
    text=True,
    encoding="utf-8",
    errors="replace",
    bufsize=1,
    env=env,
)

for line in proc.stdout:
    print(line, end="")

proc.wait()
print(f"Код завершения: {proc.returncode}")
```

HTML-граф после выполнения можно открыть в браузере из `results/` или встроить в Notebook через `IPython.display.IFrame`.
